## 2. Implemented Corrections

### Correction 1: Stale Workspace / Source Suggestions & Lifecycle Invalidation (P1)
- **Root Cause**: `IntakeAssistant`'s `workspaceId` prop was not supplied by `App`, `onSessionExpired` was never consumed, and changing `workspaceId` previously only updated a ref without clearing stale suggestions. Changing the intake text did not invalidate an active draft, allowing stale suggestions to remain actionable. Stale `finally` blocks unconditionally released mutex locks.
- **Fix**:
  - Bound a local session generation in `App.tsx` (`const [sessionGeneration, setSessionGeneration] = useState(1)`), incremented on every successful workspace initialization in `handleStartWorkspace`.
  - Supplied `workspaceId={`session-${sessionGeneration}`}` to `IntakeAssistant`.
  - Added an effect in `IntakeAssistant.tsx` on `workspaceId`: aborts any in-flight request (`abortControllerRef.current?.abort()`), increments `requestIdRef.current`, resets lock state, and clears `suggestion`, `appliedNotice`, and `intakeError` while strictly preserving the user's typed intake text in `inputText`.
  - Updated textarea `onChange`: immediately clears `suggestion` and `appliedNotice` so that an advisory suggestion is never actionable against modified source text.
  - Consumed `onSessionExpired` on 401 responses to clear any draft previously applied to `RequestForm`, while `IntakeAssistant` displays an inline 401 banner with an actionable `Start Synthetic Workspace` button without unmounting or wiping user inputs.
  - Guarded the `finally` block in `handleInterpret`: locks and `isInterpreting` are only released if `currentRequestId === requestIdRef.current && capturedWorkspace === workspaceIdRef.current`, preventing stale background responses from releasing current mutex locks.

### Correction 2: Whole Seconds Instant Preservation (P2)
- **Root Cause**: `isoToLocalInput` in `apps/web/src/utils/dateTime.ts` formatted dates as `YYYY-MM-DDTHH:mm`, dropping whole seconds (e.g. converting `2026-09-20T10:00:37Z` to `10:00:00Z`). Existing tests floored epochs to minutes and did not assert exact epoch preservation.
- **Fix**:
  - Updated `isoToLocalInput` to format as `${year}-${month}-${day}T${hours}:${minutes}:${seconds}`, preserving exact seconds.
  - Added `step="1"` to the `#due-datetime` `<input type="datetime-local">` in `RequestForm.tsx`, allowing whole seconds to pass native browser input validation without truncation.
  - Updated `dateTime.test.ts` to assert exact epoch equality (`expect(convertedEpoch).toBe(expectedEpoch)`) for UTC strings with nonzero seconds (`2026-09-20T10:00:37.000Z`) and timezone offsets (`2026-09-20T15:30:37+05:30`).

### Correction 3: Strict M2A Interpretation Response Validation (P1)
- **Root Cause**: The interpretation response was cast via TypeScript without runtime payload verification, and provenance checks relied on loose truthiness. Out-of-contract responses (e.g. fake providers or invalid tool call counts) were displayed as validated provenance.
- **Fix**:
  - Created `apps/web/src/utils/validation.ts` implementing `validateIntakeResponse`.
  - Strictly validates root structure, disallows unexpected root fields, and ensures `draft` contains only allowed fields with strict length and enum checks (`WHEELCHAIR`, `WALKER`, `CRUTCHES`, or null; borrower 1..60 chars; pickup 1..120 chars; ISO date parseable).
  - Validates that `missing_fields` is an array strictly matching the null fields in `draft` in canonical order.
  - Enforces exact provenance literals: `framework === "strands"`, `provider === "ollama"`, `model === "llama3.2:3b"`, integer `inventory_tool_calls` between 1 and 2, and valid ISO timestamp `completed_at`.
  - Any contract violation throws `ApiClientError(502, "ASSISTANT_INVALID_OUTPUT")`, rendering a safe `role="alert"` banner with no draft and no provenance displayed, preserving user inputs.
