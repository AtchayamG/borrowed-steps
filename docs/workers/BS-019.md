### 1. Mechanical Request Envelope Ceilings

Implemented in `services/agent/src/borrowed_steps/infrastructure/groq_model.py`:
- **Maximum Serialized Wire Size**: `MAX_REQUEST_BYTES = 16_384` (16,384 bytes). Measured on the actual HTTP request body on the wire including all messages, tool specs, schemas, and JSON escaping.
- **Fixed Token Output Cap**: `FIXED_MAX_COMPLETION_TOKENS = 1024` (exact integer `1024`, rejecting booleans, floats, strings, or different integers) on both streaming tool loops and structured output calls.
- **Fixed Reasoning Effort**: `FIXED_REASONING_EFFORT = "low"`.
- **Forbidden Conflicting Fields**: Deprecated `"max_tokens"` field is strictly forbidden.
- **Completion Count (`n`)**: Must be absent (provider default 1) or exact integer `1`.
- **Target & Model Pins**: Host `api.groq.com`, path `/openai/v1/chat/completions`, model `openai/gpt-oss-20b`.

### 2. Transport Boundary Validation & Non-Debit Invariants

In `_BoundedGroqTransport.handle_async_request`:
1. Validates target URL (HTTPS, host, path, port, no query/userinfo, POST).
2. Validates serialized wire body before checking deadline, checking budget, or dispatching:
   - Body must not be empty or None.
   - Wire byte length must be `<= 16,384` bytes.
   - UTF-8 decoding must succeed.
   - JSON parsing must succeed.
   - Top-level payload must be a JSON object (`dict`).
   - `model` must be `"openai/gpt-oss-20b"`.
   - `max_completion_tokens` must be exact integer `1024` (`type(val) is int and val == 1024`).
   - `"max_tokens"` must NOT be present.
   - `reasoning_effort` must be `"low"`.
   - `n` must be absent or exact integer `1`.
3. **Non-Debit Invariant**: If any validation check fails, `GroqEnvelopeRefusedError` is raised immediately. `self._budget.charge()` is NEVER called and the inner transport is NEVER invoked. The send count (`model.sent`) remains unchanged.
4. **Error Sanitization**: Error messages contain generic descriptions without secrets, API keys, user prompts, history, or raw payloads.

### 3. SDK Configuration & Anti-Mutation Protection

In `GroqModel`:
- Constructor passes `params={"max_completion_tokens": 1024, "reasoning_effort": "low"}` to parent `OpenAIModel`.
- `format_request` enforces fixed fields and explicitly pops `"max_tokens"`.
- Both `stream()` and `structured_output()` inspect caller `kwargs` and reject mutation attempts (`max_tokens`, altered `max_completion_tokens`, altered `reasoning_effort`, `n != 1`) with `GroqEnvelopeRefusedError` without debit.
- Direct mutation to `model.config["params"]` or `model.config["model_id"]` is caught and fails closed before or at the transport boundary without debit.
- `structured_output()` explicitly handles `openai.LengthFinishReasonError` and `choice.finish_reason == "length"` by raising `ValueError("Groq structured output truncated due to length limit")` and never yielding a partial draft.
