  - Found **5 vulnerabilities** (3 High, 2 Moderate), exit code 1.
  - Saved to `apps/web/test-evidence/bs018/baseline-npm-audit.json`.
  - **Advisory Details & Workflow Execution Analysis**:
    1. `extract-zip <=2.0.1` (GHSA-jmr9-qjv8-65gv & GHSA-7pqw-9j4j-h8q3, High severity, CWE-22 Path Traversal / Arbitrary File Write):
       - Transitive path: `borrowed-steps-web -> puppeteer-core@24.43.1 -> @puppeteer/browsers@2.13.2 -> extract-zip@2.0.1`.
       - Workflow analysis: `@puppeteer/browsers` uses `extract-zip` when downloading and unpacking browser archive bundles. In our development and test workflow, `browser-verify.js` executes against existing system-installed browser binaries (Microsoft Edge or Google Chrome) directly via `executablePath`. It never downloads or unzips remote browser archives.
       - Upstream fix: `puppeteer-core@25.10.0` incorporates `@puppeteer/browsers@3.2.2`, which replaces `extract-zip` with `modern-tar`, entirely removing `extract-zip` from the dependency tree.
    2. `@vitest/mocker >=2.1.0 <4.1.11` (GHSA-82fw-gwwq-j7x9, Moderate severity, CWE-22 Path Traversal / Arbitrary File Read via redirect mock):
       - Transitive path: `borrowed-steps-web -> vitest@3.2.7 -> @vitest/mocker@3.2.7`.
       - Workflow analysis: `@vitest/mocker` provides redirect mocking capabilities when mocking module specifiers. Our test suite uses standard mock functions (`vi.fn()`) and fixture-based API mocks in `src/test/mocks/mockBackend.ts` without dynamic redirect mocking.
       - Upstream fix: Upstream patched this vulnerability in `@vitest/mocker@4.1.11` and `@vitest/mocker@5.0.0` (`vitest@5.0.0`).
