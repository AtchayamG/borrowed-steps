## 1. Objective & Implemented Changes

Implemented the complete M2B Coordination web interface slice under `apps/web/` strictly adhering to the frozen `docs/M2B_CONTRACT.md`, domain layer hierarchy (`domain <- application <- interfaces/infrastructure`), and human-in-the-loop safety principles.

### Implemented:
1. **Typed Snapshot Adapter & Strict Runtime Validation** (`apps/web/src/types/api.ts`, `apps/web/src/utils/validation.ts`, `apps/web/src/api/client.ts`):
   - Added `CoordinationTaskKind` (`"PICKUP_DUE" | "RETURN_DUE"`), `CoordinationTaskStatus` (`"PENDING" | "DUE" | "RESOLVED"`), and `CoordinationTask` interface.
   - Updated `Snapshot` interface to require `tasks: CoordinationTask[]`.
   - Exported standalone `validateSnapshot(data: unknown): Snapshot` function.
   - Strictly validates `tasks` array: missing `tasks` property throws `502 SNAPSHOT_INVALID_OUTPUT`.
   - Rejects unknown properties on tasks (e.g. rejects `workspace_id` to prevent entity leakage).
   - Validates required strings (`task_id`, `loan_id`, `request_id`, `equipment_id`), valid enums (`kind`, `status`), and timezone-aware UTC ISO timestamps (`due_at`, `created_at`, `updated_at`) with leap year, calendar month/day boundaries, and UTC offset checks. Empty task arrays (`tasks: []`) are valid.
   - Wired `validateSnapshot` into `api.getSnapshot()` and `api.createWorkspace()`.

2. **Coordination Interface Component** (`apps/web/src/components/CoordinationSection.tsx`):
   - Structured layout with accessible heading (`h2` "Coordination") and explanatory scope note: *"In-app operational tasks for volunteers. Reminders and due notices are tracked within this workspace only (no external email/SMS)."*
   - Active Tasks:
     - **Arrange pickup** (`PICKUP_DUE`): displays borrower request pickup location, linked borrower name and equipment item (resolved strictly within the current workspace snapshot), and `PENDING` badge with notice that pickup is immediately actionable in person by a volunteer.
     - **Return due / Return reminder** (`RETURN_DUE`): displays borrower name, equipment item, exact UTC due instant, and badge reflecting server status (`PENDING` or `DUE`).
   - Resolved Tasks:
     - Folded into a native accessible `<details>` element labeled *"Resolved Coordination Tasks ({count})"* with `RESOLVED` badges.
   - State Handling:
     - Clear empty states when no tasks exist (*"No operational tasks currently require volunteer coordination."*).
     - Server status strictly governs badges; client does not compute or alter state based on local clock.
     - Zero dummy buttons: lifecycle transitions occur via existing confirmed human-approved loan pickup and return workflows in the Loan List.

3. **Application Integration & Freshness Tracking** (`apps/web/src/App.tsx`, `apps/web/src/index.css`):
   - Mounted `CoordinationSection` in the main operational view grid (`grid-main`), positioned alongside Requests and Loans.
   - Added freshness tracking displaying time elapsed since `lastSyncedAt` in the header bar.
   - Added CSS classes for task badges: `.tag-pending`, `.tag-due`, and `.tag-resolved`.
   - Updated header milestone fallback indicator to `"M2B"`.

4. **Test Fixtures & Mock Backend Updates** (`apps/web/src/test/mocks/mockBackend.ts`, `apps/web/scripts/browser-verify.js`):
   - Updated mock backend to initialize `tasks: []` in default snapshot and update milestone to `"M2B"`.
   - Added automatic task lifecycle emulation in mock backend: creating a reservation generates a `PICKUP_DUE` task (`due_at = created_at`); recording pickup marks pickup task `RESOLVED` and generates a `RETURN_DUE` task; recording return marks return task `RESOLVED`.
   - Updated browser verification script with synthetic M2B snapshot and added Test 7 validating Coordination section on desktop (1280x800) and mobile (390px).
