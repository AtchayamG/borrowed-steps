## Corrections, appended 2026-09-08 by BS-003-R3

Nothing above is edited. Three claims made in this report are corrected here,
with the source that contradicts them. Full detail in
`services/agent/test-evidence/probe-ledger.md` and `docs/workers/BS-003-R3.md`.

**1. Withdrawn: `retry_strategy=None` was not a cause of the 502s.**
This report argued that disabling the SDK retry strategy removed a
structured-output retry and so made one malformed emission fatal, and it made
that the headline decision for Codex. The installed source contradicts it. In
`strands-agents 1.54.0`, `event_loop/_retry.py` defines
`ModelRetryStrategy.is_retryable` as
`return isinstance(exception, ModelThrottledException)` — the default strategy
retries nothing else. `StructuredOutputException` is raised on a separate path in
`event_loop/event_loop.py`, where the loop forces the structured-output tool and
gives up if the model still will not call it. The retry setting could not have
affected those failures in either direction, and re-enabling it would not have
cleared them. The open question this report raised is void.

`retry_strategy=None` remains set, for the narrower reason the code supports:
keeping throttle retries from making outbound requests that the turn limit does
not bound.

**2. Corrected: "Ollama's constrained decoder" did not apply to this code.**
This report explained the required-and-nullable schema improvement by saying
Ollama's constrained decoder emits the whole shape. At BS-003-R2 the schema was
passed to `Agent.invoke_async(structured_output_model=...)`, which makes the SDK
expose a structured-output *tool* and ask the model to call it. That is ordinary
tool calling and constrains nothing at the decoder. The improvement observed was
real; the mechanism given for it was wrong, and with two attempts per variant it
is not separable from run-to-run variation on a 3B model. The claim becomes
accurate only under BS-003-R3, where extraction goes through
`OwnedOllamaModel.structured_output`, which sets
`request["format"] = output_model.model_json_schema()`.

**3. The "—" counters in the probe table are unknown, not zero.**
Rows 2, 4, 5 and 8 failed before the service emitted its accounting line, so
their model-request and tool-call counts were never observed. They are unknown.
In particular they are not zero: a `StructuredOutputException` is raised after at
least one request has been sent, so each of those runs made at least one outbound
request and possibly more. Any total computed by treating "—" as 0 understates
real model traffic. BS-003-R3 closes this by writing one terminal accounting line
from the adapter's `finally` path, so failed runs are counted too.
