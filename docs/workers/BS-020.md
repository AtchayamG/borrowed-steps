### 2. Two-Stage Execution Harness

Implemented in `run_canary_stages`:
- **Shared `GroqModel`**: Both stages share a single `GroqModel` instance, cumulatively bounded by the 6-send ceiling and 110s deadline.
- **Stage 1 (Tool Selection & Execution)**:
  - Executes real Strands `Agent` (`from strands import Agent, tool`).
  - Agent selects and executes `read_inventory` tool backed by `SeedInventoryReader`.
  - Hard ceiling of 2 tool attempts. If a 3rd attempt is made, raises `CanaryToolLimitExceededError`.
  - If turn 1 yields no tool call, dispatches at most one recovery prompt (`"Please check inventory using read_inventory before proceeding."`). If tool is still omitted, raises `CanaryToolNotExecutedError`.
- **Stage 2 (Structured Extraction & Source Grounding)**:
  - Precondition: requires at least 1 recorded successful tool call from stage 1.
  - Calls `model.structured_output(_Extraction, stage2_prompt)` using source-only message history.
  - Grounding assertions: extracted `borrower_label`, `equipment_kind`, `pickup_location`, and `due_at` must match exact verbatim substrings of the candidate fixture string.
  - If any field fails exact quote matching, raises `CanaryGroundingAssertionError`.
  - Zero database writes or draft emissions.
- **Guaranteed Cleanup**:
  - Transport and model cleanup (`await model.aclose()`) is guaranteed in an owned `finally:` block across all success and error paths.

### 3. Fail-Closed Network & Credential Isolation

- **Zero Egress**: Transport intercepts all HTTP requests. Any target host other than `api.groq.com` or scheme other than HTTPS immediately raises `GroqTargetRefusedError`.
- **Explicit Dummy Key**: Default offline execution uses `DUMMY_GROQ_API_KEY = "gsk_offline_dummy_key_do_not_use"`.
- **No Live CLI Mode**: Script CLI provides only offline execution (`main()`) and `--plan-only` flag. It provides no `--live` flag and rejects unknown arguments.
- **Environment Isolation**: Script does not inspect `GROQ_API_KEY` from OS environment variables.
