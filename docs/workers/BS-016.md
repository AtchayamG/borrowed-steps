## Implemented and Verified

Implemented the operational HTTP endpoints and packaging for the Borrowed Steps hosted scheduler, fulfilling all requirements of `docs/M3_SCHEDULER_HTTP_CONTRACT.md` and `docs/M3_OPERATIONS_CONTRACT.md` over the accepted BS-014 foundation. The solution was verified against a real disposable PostgreSQL 16.10 test cluster. Local runtime mode, domain logic, and provider behavior remain strictly unaltered.

All contract requirements and security invariants were satisfied:

1. **Shifted Schema Readiness from Factory-Time to Request-Time**:
   - Removed blocking `store.check_schema()` from `create_app()`, enabling instantaneous zero-DB cold-start initialization.
   - Added synchronous FastAPI dependency `require_hosted_schema` offloaded to Starlette's threadpool (`anyio.to_thread.run_sync`) on all 7 standard business routes (`post_workspace`, `get_snapshot`, `post_request`, `post_reservation`, `post_pickup`, `post_return`, `post_inspection`).
   - Unmigrated databases (version 0) or future schemas (version > 2) return generic 503 `SERVICE_UNAVAILABLE`.
   - Health endpoint (`GET /api/health`) remains purely liveness, opening zero database connections.

2. **Zero-DB Cold-Start Bearer Authentication**:
   - Implemented in `_authenticate_operational(http_request)`: evaluates headers completely in-memory before invoking `HostedSchedulerService` or any psycopg driver functions.
   - Requires exactly one `Authorization` header starting with `Bearer `.
   - Constant-time verification with `hmac.compare_digest` against configured `task_tick_token`.
   - Missing, malformed, empty, duplicate headers, or cookie-only sessions return generic 401 `UNAUTHORIZED` without allocating database connections.
   - Verified via `psycopg.connect` instrumented probe in `test_unauthenticated_cold_start_causes_zero_database_connections`.
   - Missing/unconfigured `task_tick_token` returns generic 503 `SERVICE_UNAVAILABLE` before database connection.

3. **Operational Endpoints (`/api/internal/tasks/tick` & `/api/internal/tasks/status`)**:
   - Registered exclusively when `BS_RUNTIME=hosted`. Completely omitted in `local` runtime mode (returns 404).
   - Hidden from public OpenAPI documentation (`include_in_schema=False`).
   - Disregard all body payloads and query parameters; candidate limit (100), processing budget (20s), and lease duration (60s) cannot be overridden.
   - `POST /api/internal/tasks/tick`: invokes `HostedSchedulerService.tick()`. Status codes:
     - 200: Outcome `success` or `partial`.
     - 409: Outcome `busy` or `stale_lease`.
     - 503: Outcome `failed`, unmigrated schema, or evidence write failure.
     - Response schema contains `outcome`, `capacity_limited`, and aggregate `counts` (or null). Internal `run_id` and driver/error details are strictly omitted.
   - `GET /api/internal/tasks/status`: strictly read-only; calls `read_status()` without mutating state or running tasks. Returns 200 on success, 503 on database read error.
   - Returns `Cache-Control: no-store` on all operational responses.

4. **Configuration & Token Handling (`config.py`)**:
   - Added `task_tick_token: str | None = field(default=None, repr=False)` to `Settings`.
   - Validated in `validate_settings` and `load_settings`: must contain 32..256 ASCII URL-safe characters (`[A-Za-z0-9_-]`).
   - Exact matching without stripping/trimming; redacted from `repr(settings)` and error strings.

5. **Inactive GitHub Actions Workflow Example (`docs/workflows/hosted-tick.yml.example`)**:
