### 2. Durable Canary Receipt Domain & Storage Boundary

Implemented in `services/agent/src/borrowed_steps/infrastructure/canary_receipt.py`:
- **Constants**:
  - `ACCEPTED_PLAN_HASH = "38ec48176db21d7f947cfdc1ae1b3b211efdbdb55c976043462aea85a16a3031"` (exact accepted BS-020 candidate plan hash)
  - `ACCEPTED_PROVIDER = "groq"`
  - `ACCEPTED_MODEL = "openai/gpt-oss-20b"`
  - `MAX_RESERVED_SENDS = 6`
  - `MAX_RESERVED_TOKENS = 1024`
- **State Machine**:
  - `CanaryState`: `RESERVED`, `DISPATCHED`, `SUCCEEDED`, `FAILED_CONFIRMED`, `UNCERTAIN`.
  - Legal transitions:
    - `RESERVED -> DISPATCHED` (requires non-expired authorization, sets `dispatched_at`)
    - `DISPATCHED -> SUCCEEDED` (terminal; records `actual_sends`, `actual_tokens`, clears `concurrency_active`)
    - `DISPATCHED -> FAILED_CONFIRMED` (terminal; records `error_category`, `error_reason`, clears `concurrency_active`)
    - `DISPATCHED -> UNCERTAIN` (terminal for dispatch; retains full reserved sends/tokens as actual debit, preserves `concurrency_active=True` to block future canaries)
  - Illegal transitions strictly rejected via `CanaryIllegalStateTransitionError`.
- **Conservative Debit Retention**:
  - `mark_uncertain`: retains 100% of reserved sends (6) and tokens (1024) as actual debit (`actual_sends = reserved_sends`, `actual_tokens = reserved_tokens`).
  - Keeps `concurrency_active = TRUE`, preventing any new canary reservation database-wide.
- **Explicit Human Recovery**:
  - `record_recovery`: requires non-empty `recovery_reason` and human operator context.
  - Updates `concurrency_active = FALSE`, `recovered_at = now`, and stores `recovery_reason`.
  - Never refunds reserved sends or tokens; never modifies receipt state back to dispatchable.
- **Short Transaction Discipline**:
  - All database interactions use short transactions with statement timeout (5,000 ms) and lock timeout (2,000 ms).
  - Transactions are committed or rolled back immediately; no database transaction is held across HTTP/inference calls.
  - `require_transport_security=True` enforces TLS connection parameters.
- **Replay vs Conflict**:
  - `reserve` checks existing `receipt_id`. If existing `payload_hash` matches canonical SHA-256 digest, returns existing immutable record (idempotent replay).
  - If existing `payload_hash` differs, raises `CanaryConflictError`.
- **Fail-Closed Validation**:
  - `validate_reservation_request` validates:
    - Non-empty `receipt_id`.
    - Authorization present, `live_authorized=True`, non-empty id, and not expired.
    - Plan present, `live_authorized=True`, plan hash exactly matches `ACCEPTED_PLAN_HASH`, provider matches `ACCEPTED_PROVIDER`, model matches `ACCEPTED_MODEL`.
    - Limit widening rejected: `reserved_sends` between 1 and 6, `reserved_tokens` between 1 and 1024.
- **Dual Store Implementations**:
  - `CanaryReceiptStore`: production PostgreSQL store using psycopg.
  - `InMemoryCanaryReceiptStore`: thread-safe in-memory implementation for offline testing without running PostgreSQL.
