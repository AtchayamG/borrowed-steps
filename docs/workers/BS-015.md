### Key Deliverables & Verified Points

1. **Offline Wire Probe (`services/agent/scripts/admission_probe.py`)**:
   - Built a standalone probe executing strictly offline using a custom `OfflineProbeTransport` that refuses any live network transport or unexpected target URLs (`ALLOWED_HOST = "api.groq.com"`, `ALLOWED_PATH = "/openai/v1/chat/completions"`).
   - Intercepted real wire payloads produced by Strands 1.54.0 and OpenAI 2.54.0 SDKs.
   - Evaluated maximum 2,000-character intake text (`INTAKE_TEXT_MAX_LENGTH`), testing both ASCII English and multilingual Unicode (English, Tamil, Devanagari, German, French, and emoji symbols).
   - Incorporated real Strands `read_inventory` tool specification and real `SEED_EQUIPMENT` inventory counts (`RealSeedInventoryReader`).
   - Evaluated Stage 1 tool proposal and multi-turn prompt accumulation, plus Stage 2 structured output with `_Extraction` schema.
   - Verified that a 7th send attempt is strictly blocked by sticky budget enforcement (`GroqSendBudgetExceededError`).
   - Persisted complete sanitized measurements to `services/agent/test-evidence/bs015/probe_measurements.json`.

2. **Empirical Wire Measurements & Token Upper Bounds**:
   - **Happy Path ASCII (3 Sends)**: Send 1 = 2,928 B, Send 2 = 3,327 B (+399 B accumulation), Send 3 = 5,624 B (Stage 2 schema overhead: 1,029 B `response_format` + 720 B system prompt schema). Cumulative wire payload: **11,879 bytes**.
   - **Happy Path Multilingual Unicode (3 Sends)**: Send 1 = 3,690 B (ratio 1.260), Send 2 = 4,089 B (ratio 1.229), Send 3 = 6,386 B (ratio 1.135). Cumulative wire payload: **14,165 bytes** (+2,286 B expansion over ASCII).
   - **Worst-Case 6 Sends**: Evaluated multi-turn recovery, tool repetition, and 429 retry: **24,826 cumulative wire bytes**.
   - **Token Upper Bounds & Debunking `chars // 4`**: Proved that naive `chars // 4` estimation understates token usage by 3x–5x on Unicode text, dense JSON formatting, dual schema overhead (1,749 bytes), and provider reasoning/chat templates.

3. **Relational Admission Design (`docs/GROQ_ADMISSION_PROPOSAL.md`)**:
   - Designed minimal PostgreSQL-based coordinator (`inference_admission` table, Migration V3) with zero external message brokers, Redis, or heartbeat daemons.
   - Enforces single organization-wide concurrency owner and per-workspace fairness.
   - Operates on short atomic database transactions (<5ms); never holds database transactions across network inference.
   - Employs database clock (`CURRENT_TIMESTAMP`) and 65-second conservative rolling window boundaries.

4. **State Machine & Safe Uncertainty Invariants**:
   - State-transition table: `admitted` -> `send_reserved` -> `sent` -> `cleanup_confirmed` / `uncertain`.
   - **Safe Uncertainty Rule**: Timed-out, dropped, or crashed inference transitions to `uncertain` and retains its full token debit permanently. No credit refund is issued, ensuring local ledger never underestimates organization consumption against remote Groq rate limits.
   - Stale process recovery protected by monotonic `fence_token` validation before wire dispatch.

5. **Conservative Throughput Computations**:
   - Evaluated against Groq reference limits: 30 RPM / 1,000 RPD / 8,000 TPM / 200,000 TPD.
   - **Key Finding**: TPM (8,000 Tokens/Min) is the primary bottleneck by a factor of 3x to 10x.
   - A single happy-path intake consumes ~3,430 to ~4,600 tokens (43%–58% of TPM limit).
   - Maximum organization capacity is **1 to 2 intakes per minute** and **29 to 58 intakes per day**.
   - Proposed Option 1 (Strict Single-Flight Concurrency with 30s spacing) to guarantee zero 429 errors.

6. **Implementation File List, Test Matrix & Live Proof Gates**:
