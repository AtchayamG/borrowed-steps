## IMPLEMENTED

**1. The local provider is pinned again.** `BS_ASSISTANT_HOST` and
`BS_ASSISTANT_MODEL` no longer configure anything. `load_settings` raises
`ValueError` when either is set to a value other than the pinned
`http://127.0.0.1:11434` / `llama3.2:3b`, so a remote endpoint or a different
model fails at startup instead of being used silently. Unset, or set to exactly
the pinned value, is accepted. The explicit test seam is unchanged and separate:
`create_app(..., interpreter=...)` still injects a fake, and the adapter
constructor still takes host and model for its own tests.

**2. The tool budget bounds the whole invocation.** `_ToolBudget` already counted
attempts, but only `success_count` was checked after the run. The SDK converts an
ordinary tool exception into a tool-error result and lets the model carry on, so
two successful reads plus a refused third could still finish with valid
structured output and `success_count == 2` and be reported as a success. The
adapter now fails the entire invocation with 502 when attempts exceed two,
regardless of what the model produced afterwards. Real successful tool metrics
are still required on top of that.

**3. Stalls and cancellation are finite, and the bound is proven.**
- The ollama client is constructed with `ollama_client_args={"timeout": 60.0}`.
  Its default is `None`, i.e. no timeout at all, which is what allowed a stalled
  provider to hold the single slot indefinitely.
- The adapter wraps its own run in `asyncio.timeout(110 s)`, inside the contract's
  120 s. Unlike the cooperative signal alone, this actually cancels the run at its
  next await point, so the invocation always ends and the slot is always released.
  The cooperative `cancel_signal` is still passed first so the SDK can stop
  cleanly. The route keeps its 120 s guard as an outer backstop and still holds
  the slot until the owned run is done, so there is no overlap and no orphan.
- The model-request bound is now proven rather than assumed: a test drives the
  **real Strands agent loop** against a fake `Model` that never stops asking for a
  tool, and counts actual `Model` invocations. It observes exactly 6 and
  `stop_reason == "limit_turns"`, which the adapter maps to 502.

No SDK file was patched, no queue or job service was added, and the architecture
is unchanged. One SDK limitation could not be fixed from here and is documented
rather than papered over: `OllamaModel.stream` creates an `ollama.AsyncClient` per
stream and never closes it, and that client is not reachable from this code. The
finite transport timeout is the mitigation.
