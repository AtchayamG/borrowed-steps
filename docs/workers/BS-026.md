## 1. Executive Summary & Objective

In accordance with `docs/M3_ADMISSION_DECISION.md`, BS-026 implements the bounded storage boundary for inference admission in PostgreSQL. 

The architecture enforces a strict separation of concerns:
- **Groq Provider**: Enforces provider token quotas (TPM/TPD, account limits, 429 status).
- **PostgreSQL (`InferenceAdmissionStore`)**: Enforces application request allowances across distributed instances, a single active operation invariant, rolling time windows, and safe stale recovery.
- **No Local Guarantees**: Does NOT label output tokens as a total-token guarantee, does NOT estimate input tokens from bytes, and does NOT promise 20 daily successful interpretations.

### Core Governance & Commitments
- **Hosted Public Assistant State**: Strictly **DISABLED** (`BS_ASSISTANT_ENABLED=0`).
- **Spend & Provider Calls**: ₹0.00 / $0.00 spend, zero live Groq provider calls, zero credential discovery/reading, zero cloud mutations.
- **Fail-Closed Concurrency**: Expired stored deadlines never auto-release; stale or orphaned executions require explicit operator recovery.

## 3. Storage Boundary Implementation (`InferenceAdmissionStore`)

Implemented in `services/agent/src/borrowed_steps/infrastructure/inference_admission.py`.

### Policy Constants
- `RESERVED_SENDS = 6`: Fixed reservation per operation. Never refunded.
- `GLOBAL_LIMIT_60S = 6`: Global rolling 60-second reservation cap (1 operation max).
- `GLOBAL_LIMIT_24H = 120`: Global rolling 24-hour cap (20 operations max).
- `WORKSPACE_LIMIT_24H = 24`: Per-workspace rolling 24-hour cap (4 operations max).
- `STORED_DEADLINE_SECONDS = 120`: Stored deadline to identify stale operations (never auto-released).
- `PROVIDER_429_COOLDOWN_SECONDS = 900`: Durable 15-minute global cooldown after confirmed provider 429.
- `STATEMENT_TIMEOUT_MS = 5000`, `LOCK_TIMEOUT_MS = 2000`.

### Methods & Lifecycle
1. **`reserve(request: AdmissionReservationRequest) -> AdmissionRecord`**:
   - Takes transaction advisory lock `_ADMISSION_LOCK = 8_801_103_331_031`.
   - Rejects if provider 429 cooldown active, another operation active, or any rolling send cap exceeded.
   - Evaluates rolling windows using database time (`NOW() AT TIME ZONE 'UTC'`). Active rows count their full 6 sends indefinitely; released rows count until `released_at + window`.
   - Exact replay returns existing record; conflicting identity or hashes raises `AdmissionReplayConflictError`.
2. **`mark_dispatched(reservation_id, owner_execution_id) -> None`**:
   - Permits exactly one transition from `RESERVED` -> `DISPATCHED` before provider transport.
   - Rejects expired deadlines without auto-releasing.
3. **`finish(reservation_id, owner_execution_id, state, cleanup_completed, ...) -> AdmissionRecord`**:
   - Transitions `DISPATCHED` to `SUCCEEDED`, `FAILED_CONFIRMED`, or `UNCERTAIN`.
   - Confirmed terminal states (`SUCCEEDED`, `FAILED_CONFIRMED`) strictly require `cleanup_completed=True`.
   - `UNCERTAIN` stays active (`is_active=True`, `released_at=None`) to preserve concurrency locking until explicit recovery.
   - Exact replay returns record; conflicting replay refuses.
4. **`recover_dead(reservation_id, operator_execution_id, reason, confirmed_dead) -> AdmissionRecord`**:
   - Transitions `RESERVED`, `DISPATCHED`, or `UNCERTAIN` to `RECOVERED`.
   - Sets `is_active=False` and stamps `released_at = NOW() AT TIME ZONE 'UTC'` (starting fresh debit window).
   - Refuses recovery of confirmed terminal states.
5. **`get`, `get_active`, `get_by_request_key`**: Safe read queries.
