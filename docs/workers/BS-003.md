## WHY THIS IS BLOCKED

Acceptance criterion 6 requires a bounded real proof covering full explicit
fields, missing/relative-date clarification, actual inventory tool execution and
an unchanged business snapshot. Five real invocations were spent, which is the
whole budget. Three of the four sub-goals are proven. Two are not:

1. **`due_at` never populated**, even from a message containing a complete
   ISO-8601 timestamp with an offset. Whether the model returned null itself or
   proposed a reformatted timestamp that grounding then rejected was **not
   determined**: the adapter's field-name-only diagnostic logs at DEBUG, and
   uvicorn's `--log-level debug` configures only the `uvicorn.*` loggers, so it
   never emitted. The budget was exhausted before this could be re-run, so the
   cause is recorded as unknown rather than guessed.
2. **The dedicated relative-date case returned 502, not a draft.** The model did
   not call `read_inventory`, so the adapter refused rather than fabricating
   provenance — correct contract behaviour, but it means that specific
   demonstration did not happen. The server log records the exact reason:
   `Assistant inventory tool executions out of bounds: 0`.

Root cause of (2) is observable and worth a decision: Strands passes a forced
tool choice, and the Ollama provider ignores it. The SDK says so itself, in a
warning captured during the run:
`UserWarning: A ToolChoice was provided to this provider but is not supported and
will be ignored`. So `llama3.2:3b` is free to skip the tool, and did on one of
three inputs. The failure is safe — 502, no draft, no writes — but interpretation
is not dependable on this model without a change of approach.

The contract says to stop and report BLOCKED if model reliability fails the
bounded probe, and not to download or swap models. That is what this is. The
decision about what to do next is Codex's, not mine; options are listed under
REVIEW_REQUEST.

## IMPLEMENTED

- **Application port.** `application/interpreter.py`: stdlib `RequestInterpreter`
  protocol with `DraftRequest`, `Interpretation`, `InventoryCount` and a read-only
  `InventoryReader`. No Strands, Pydantic or Ollama anywhere in it.
- **Grounding.** `application/grounding.py`, stdlib and model-free. A value is
  only accepted when it equals the evidence substring the extractor claimed and
  that substring occurs in the text; equipment kind needs exactly one unambiguous
  lexical match; `due_at` must be a complete timezone-aware ISO-8601 quote that
  also passes the existing M1 window rule. Everything else becomes null.
- **Real adapter.** `infrastructure/strands_interpreter.py`: a fresh `Agent` per
  invocation, an explicit `OllamaModel(host, model_id)`, `callback_handler=None`
  so nothing is printed, exactly one read-only tool, `structured_output_model`
  for extraction, and real SDK bounds — `Limits(turns=6)` and `cancel_signal` —
  taken from the installed SDK, not invented. Provenance is built here from
  `metrics.tool_metrics["read_inventory"].success_count`; a run with zero
  successful tool executions is refused.
- **Workspace-bound inventory.** `infrastructure/inventory.py` counts equipment
  by kind and readiness state for one workspace. The tool takes no `workspace_id`
  argument, returns no identity, and opens and closes its own short read
  transaction, so no transaction is ever held during inference.
- **HTTP.** `POST /api/intake/interpret` with the exact contract shapes and
  errors, the same session and Origin protection as other POST routes, and an
  explicit exemption from `Idempotency-Key`. `health.milestone` is now `"M2A"`
  and `agent_mode` is `"disabled"` or `"strands_ollama"` from configuration only.
- **Limits.** `interfaces/http/inference_slot.py` gives one non-queuing slot
  (429 when taken). The route applies a 120 s deadline with `asyncio.wait_for`
  over a shielded task; on timeout it sets the SDK's cooperative cancel signal
  and deliberately does **not** hard-cancel the task, so the slot stays held
  until the owned inference truly ends.
- **Config.** `BS_ASSISTANT_ENABLED` defaults false. When off, no provider module
  is imported at all and the entire structured workflow is unaffected.

1. Ollama ignores Strands' forced tool choice, so the model may skip
   `read_inventory` and the request then fails with 502. One of three inputs in
   the probe. Safe, but not dependable.
2. `due_at` did not populate from an explicit ISO-8601 timestamp; cause
   undetermined, budget exhausted.
3. The grounding diagnostic is invisible under `uvicorn --log-level debug`,
   because that configures only the `uvicorn.*` loggers. Documented; a small
   logging-config change would fix it.
4. First call after model load took 46.7 s. Inside the deadline, but a cold start
   plus a slower machine could approach 120 s.
5. The inventory read is synchronous inside the async tool. It is a single
   indexed query on a local file, but it does briefly occupy the event loop.
6. Sample size is three inputs. Nothing here is a measured reliability rate.
