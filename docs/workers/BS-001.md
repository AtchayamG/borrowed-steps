## IMPLEMENTED

- Python 3.11+ package `services/agent/src/borrowed_steps`, dependencies pointing
  inward only: `domain <- application <- interfaces/infrastructure`.
- **Domain** (standard library only, no FastAPI/Pydantic/sqlite3/Strands import):
  entities and enumerations in `domain/models.py`; deterministic transition rules
  in `domain/rules.py` (reserve, pick up, return, inspect, close, the 30-day
  `due_at` window, and the human-approval requirement); coded errors in
  `domain/errors.py`.
- **Application**: `application/ports.py` defines a small `Store` /
  `WorkspaceUnitOfWork` unit-of-work port plus `Clock` and `IdGenerator` seams;
  `application/use_cases.py` holds every workflow decision, enforces human
  approval server-side for allocation, pickup, return and every inspection
  outcome including quarantine release, and scopes all work to one workspace.
- **Infrastructure**: `infrastructure/sqlite_store.py`, a file-backed `sqlite3`
  adapter with numbered migrations, `PRAGMA foreign_keys = ON`, WAL, a 5 s busy
  timeout, `BEGIN IMMEDIATE` write transactions, deferred read transactions, and
  the partial unique index `ux_loans_active_equipment` that makes a second open
  loan on one item impossible. `infrastructure/system.py` supplies the real clock
  and CSPRNG identifiers.
- **HTTP adapter**: `interfaces/http/app.py` implements every M1 route with the
  exact contract shapes, the session cookie (`bs_session`, HttpOnly, SameSite=Lax,
  24 h, `Secure` when configured), the configured-Origin check on mutations, the
  `Idempotency-Key` requirement, one shared mutation runner that applies the
  effect and stores its response inside a single transaction, and a stable error
  envelope that never emits a framework trace.
  `interfaces/http/schemas.py` holds strict request schemas that reject unknown
  fields, loose numeric and boolean coercion, naive timestamps and bare epoch
  numbers.
- `config.py` (environment settings, no secrets), `isotime.py` (UTC ISO-8601
  normalisation), `main.py` (`borrowed_steps.main:app`).
- `scripts/smoke.py`, a standard-library HTTP smoke against a running server.
- `docs/BACKEND_SETUP.md` with Windows setup, pinned dependencies, migration
  behaviour, configuration, the exact check commands and the start command bound
  to `127.0.0.1:8000`.

## KNOWN_ISSUES

1. FastAPI validates the request body before the handler runs, so a malformed
   body sent without a session returns `422 VALIDATION_ERROR` rather than
   `401 SESSION_REQUIRED`. The contract does not fix a precedence. Nothing leaks:
   the message is generic and no workspace is touched.
2. Expired session rows are never swept. Harmless for a local M1 file, but a
   public deployment needs a sweep or a TTL job before M3.
3. No background due-date processing and no due reminder. Both are M2 scope by
   design, and nothing in this code implies a notice was delivered.
4. No Strands, no AgentCore, no deployment. M2 and M3 gates, deliberately absent.
5. `requirements.lock` was produced on Windows and pins the resolved set for that
   platform. A Linux release environment will need its own resolve at M3.

## ARCHITECTURE_DEVIATIONS

None. Two structural choices worth naming, both inside the stated boundaries:

- `CodedError` is the shared base in `domain/errors.py`; `DomainError` marks the
  subset raised by the loan rules, and the application and HTTP layers subclass
  `CodedError` for `NOT_FOUND`, `SESSION_REQUIRED`, `IDEMPOTENCY_CONFLICT` and
  `ORIGIN_FORBIDDEN`. Outer layers importing an inner base keeps the dependency
  direction inward and gives the adapter one error handler.
- `isotime.py` is a leaf module at the package root with no imports from any
  layer, so the infrastructure and HTTP adapters can share one UTC ISO-8601
  representation without importing each other.

## Correction, added by BS-001-R1

Codex's independent review of commit 5a5e441 found three defects and one
maintenance issue. Two claims in the report above were stronger than the
evidence actually supported, and are corrected here rather than left standing:

1. **"byte for byte" was wrong.** The tests at 5a5e441 asserted
   `first.json() == second.json()`, which is decoded-value equality. The initial
   response serialised the payload in insertion order while the replay
   re-serialised the stored JSON with sorted keys, so the two responses carried
   the same values in different bytes. Fixed in BS-001-R1: the body is now
   serialised once, stored, and served verbatim on both paths, and the tests
   assert `.content` equality for all five mutation families, a non-ASCII label
   and a replay after reopening the database.
2. **"a stable error envelope that never emits a framework trace" was
   incomplete.** There was no catch-all handler, so an unexpected exception
   returned Starlette's `text/plain` "Internal Server Error" rather than the
   frozen JSON envelope. Rollback was already correct. Fixed in BS-001-R1 with
   an `INTERNAL_ERROR` envelope plus server-side diagnostic logging.

Also fixed in BS-001-R1: `POST /api/workspaces` accepted a missing body and
`null` because the parameter was optional, and `scripts/smoke.py` hardcoded a
`due_at` that would expire during judging.

Full detail, reproductions and evidence: `docs/workers/BS-001-R1.md`.
