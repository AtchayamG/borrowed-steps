## IMPLEMENTED

**1. Identical response bytes on first response and replay.**
`interfaces/http/app.py` gains `_serialise()` and `_stored_response()`. A
mutation body is now serialised exactly once, with canonical sorted keys and
`ensure_ascii=False`, stored alongside its effect in the same transaction, and
served from that stored text on both the first response and every replay, as
`Response(content=..., media_type="application/json")`. The previous code
serialised twice with different options, so the values matched but the bytes did
not. `run_mutation` and the five mutation routes now return `Response`. The
effect and the stored response remain atomic; no duplicate events.

**2. Generic unexpected-error envelope.**
A catch-all `@app.exception_handler(Exception)` returns HTTP 500 with exactly
`{"error":{"code":"INTERNAL_ERROR","message":"The request could not be completed."}}`
and `Content-Type: application/json`. No exception type, message or traceback
reaches the client. The detail is logged server-side through the new
`borrowed_steps.http` logger with `exc_info`. Rollback is untouched: the storage
context manager has already unwound the transaction before the handler runs.

**3. `POST /api/workspaces` requires an empty JSON object.**
The body parameter changed from `WorkspaceBody | None = None` to a required
`WorkspaceBody`. A missing body, `null`, an array, a bare scalar and any unknown
field are now refused with 422 before the handler runs, so no workspace, session
or equipment row is created and no cookie is issued. `{}` still returns 201.

**4. Live smoke date is relative.**
`scripts/smoke.py` computes `due_at` as `datetime.now(UTC) + 7 days` instead of
the hardcoded `2026-09-20`, so the smoke stays valid through judging. The smoke
also now captures the raw response bytes and asserts that the idempotent replay
is byte-identical and `application/json`, so the headline fix is proven over real
HTTP and not only in-process. Frozen-clock unit fixtures are unchanged and still
deterministic.

Supporting change: `SqliteUnitOfWork` is added to
`infrastructure/sqlite_store.py`'s `__all__`, because the failure-injection tests
patch it.

## KNOWN_ISSUES

1. Successful mutation responses now use canonical sorted key order rather than
   insertion order. JSON object key order is not contract-significant and no
   client should depend on it, but it is an observable change from 5a5e441.
2. Non-ASCII text is served as raw UTF-8 rather than `\uXXXX` escapes. Both are
   valid JSON; this is noted because it changes response bytes for such labels.
3. Carried over from BS-001, all accepted by the review as later gates: expired
   session rows are never swept; validation still runs before session resolution
   for malformed bodies; no background due processing; no Strands, AgentCore or
   deployment; `requirements.lock` is a Windows resolve and M3 will need its own.
